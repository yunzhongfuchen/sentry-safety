# Worklog Skill 设计文档

## 目标
创建一个 Claude skill，用于根据用户与 Claude 的对话自动总结每日工作内容，生成结构化的日报和周报 Markdown 文件。

## 使用场景
- 用户在日常开发工作中与 Claude 协作（编码、调试、讨论方案等）。
- 用户需要定期向团队或上级汇报工作进展。
- 用户希望减少手动整理工作日志的时间，将对话内容自动转化为可追溯的文档。

## 核心功能

### 1. 自动工作检测与记录
在对话过程中，skill 自动识别用户完成的工作事项，并追加到当日草稿文件。

- **小事（静默记录）**：配置调整、文档更新、小型重构、临时脚本等。skill 直接写入草稿，不打扰用户。
- **大事（用户确认）**：Bug 修复、新功能完成、跨文件重构、合并提交、性能优化等。skill 询问用户是否记录，确认后写入草稿。

**状态过滤规则**：
- 优先匹配完成态表述（"已经/刚刚/解决了/完成了/提交了/合并了"）。
- 忽略将来态（"准备/计划/明天/下次"）和假设态（"也许/可能/试试"）。
- 如果 5 分钟内同一话题被推翻，自动标记前一条为无效。

### 2. 主动记录
用户随时可以通过指令将事项追加到当日草稿，例如：
- "记录：下午要开会讨论方案"
- "记一下，明天需要联调接口"

### 3. 日报生成
用户触发"生成日报"后，skill：
1. 读取当日草稿文件。
2. 分析当前会话对话，补全草稿中未包含的内容。
3. 去重、合并、按时间排序。
4. 自动分类：功能、Bug修复、优化、文档、其他。
5. 填充到 Markdown 模板，输出到 `~/worklogs/YYYY-MM-DD-daily.md`。
6. 清空当日草稿。

**输出方式**：直接保存到文件，仅向用户报告文件路径，不将完整内容打印在对话中。

### 4. 周报生成
用户触发"生成周报"后，skill：
1. 扫描 `~/worklogs/`，读取本周所有日报文件。
2. 按分类汇总，去重。
3. 统计数字（完成功能数、修复 Bug 数等）。
4. 汇总"明日计划"作为"下周计划"。
5. 输出到 `~/worklogs/YYYY-weekNN.md`。

### 5. 草稿管理
- 草稿文件按日期命名（`.draft-YYYY-MM-DD.md`）。
- 同一天的所有 Claude 会话窗口共享同一个草稿文件（追加写入）。
- 不同日期的会话使用独立草稿文件。
- 日报生成后清空当日草稿（或保留 `.bak` 备份）。

## 文件结构

```
~/worklogs/
├── .draft-2026-05-14.md          # 当日草稿（临时）
├── 2026-05-13-daily.md           # 已生成的日报
├── 2026-05-14-daily.md           # 已生成的日报
├── 2026-week20.md                # 已生成的周报
└── .worklog-skill-config.json    # 用户偏好配置（可选）
```

## 日报模板

```markdown
# 工作日报 — YYYY-MM-DD

## 今日完成

### [功能]
- xxx

### [Bug修复]
- xxx

### [优化]
- xxx

### [文档]
- xxx

### [其他]
- xxx

## 进行中
- xxx

## 明日计划
- xxx

## 备注
- 自动记录 X 条，手动记录 Y 条
```

## 周报模板

```markdown
# 工作周报 — YYYY-MM-DD 至 YYYY-MM-DD

## 本周概览
- 完成功能：X 项
- 修复 Bug：Y 个
- 性能优化：Z 项
- 文档/其他：W 项

## 详细内容

### 功能开发
- MM-DD：xxx

### Bug修复
- MM-DD：xxx

### 优化
- MM-DD：xxx

## 下周计划
- xxx
```

## 触发指令

| 意图 | 触发示例 |
|------|---------|
| 主动记录 | "记录：xxx"、"记一下，xxx" |
| 生成日报 | "生成日报"、"写日报"、"今天做了什么" |
| 生成周报 | "生成周报"、"这周总结"、"周报" |
| 查看草稿 | "今天记录了什么"、"看看草稿" |
| 修改日报 | "把日报第三条删掉"、"在日报里加上 xxx" |
| 清空草稿 | "清空今天记录" |

## 边界情况处理

- **草稿不存在**：首次使用时自动创建空草稿。
- **同一天多次生成日报**：覆盖已有日报文件。
- **跨午夜**：以系统时间为准，分属不同日期。
- **用户否认**：支持"这不是工作"、"忽略刚才那条"来撤销自动检测。
- **计划未执行**：周报汇总时，若"明日计划"在下一天无对应完成记录，标记为"未完成"。
- **非工作会话**：闲聊、查资料等无工作完成信号的内容不会触发记录。

## 技术约束

- skill 无法跨会话读取 Claude 的对话历史，因此依赖本地草稿文件实现跨会话持久化。
- 草稿文件使用本地文件系统存储，不依赖 Claude 云端状态。
- 自动检测基于关键词和语义判断，可能存在误判，通过"状态过滤"和"用户确认"机制缓解。

## 非目标（明确排除）

- 不支持直接读取 Git commit 历史生成日报。
- 不支持与其他项目管理工具（Jira、Notion 等）集成。
- 不支持多语言输出（仅简体中文）。
- 不支持邮件/企业微信自动发送（仅生成文件，由用户自行分发）。
