# 报警记录数据结构文档

本文档描述视频诊断系统报警记录的完整数据结构，供外部系统设计推送接收 API 使用。

服务默认监听 `0.0.0.0:8000`，内网其他机器可通过部署机器的内网 IP 访问。

基础地址：`http://<部署机IP>:8000`

---

## 1. 记录字段总表

一条报警记录是一个 JSON 对象，字段如下：

| 字段               | 类型          | 可为空       | 说明                                                                                              |
| ------------------ | ------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| `id`             | string        | 否           | 记录唯一 ID，格式：`{camera_id}_{算法key}_{毫秒时间戳}`，如 `3_安全背心_05dc45_1784538005159` |
| `camera_id`      | string        | 否           | 摄像头唯一标识                                                                                    |
| `detection_type` | string        | 否           | 触发算法的 **key**（唯一标识，非显示名称），如`fire`、`smoke`、`安全帽_925834`，见 1.1 节                                            |
| `level`          | string        | 否           | 告警级别（机器侧判定），枚举见第 2 节                                                             |
| `status`         | string        | 否           | 处理状态（人工侧操作），枚举见第 2 节                                                             |
| `time`           | string        | 否           | 触发时间，格式`YYYY-MM-DD HH:MM:SS`，部署机本地时间                                             |
| `confidence`     | float         | 否           | 小模型置信度，0~1                                                                                 |
| `reason`         | string        | 否           | 报警说明文本，来源见第 4 节                                                                       |
| `small_model`    | object        | 否           | 小模型检测结果摘要，结构见第 3 节                                                                 |
| `vlm_review`     | object\| null | **是** | VLM 大模型复核结果，未复核时为`null`，结构见第 3 节                                             |
| `source`         | string        | 否           | 告警来源，固定为`"small_model"`                                                                 |
| `frame_count`    | int           | 否           | 关联的检测帧序列图片数量，可为 0                                                                  |

### 1.1 detection_type（算法 key）与显示名称

`detection_type` 是算法的**唯一 key**，不是显示名称。两者对应关系：

| 算法来源 | key（detection_type 的值） | 显示名称（label） |
| -------- | -------------------------- | ----------------- |
| 内置算法 | `fire`、`smoke`、`sleep` | `明火`、`烟雾`、`睡岗` |
| 界面新增 | `{显示名}_{6位随机hash}`，如 `安全帽_925834` | `安全帽` |

注意：新增算法的 key 虽包含显示名，但带 hash 后缀，不能直接当显示名用。显示名称映射可通过 `GET /algorithms` 获取（返回全部算法的 `key` / `label` / `color`）。

**建议**：推送报文中增加 `detection_label`（算法显示名）字段，接收方无需维护映射（待推送功能实现时加入）。

## 2. 枚举值

### level（告警级别，机器侧）

| 值                    | 含义                                  |
| --------------------- | ------------------------------------- |
| `small_model_alarm` | 小模型报警（初始状态，未经 VLM 复核） |
| `vlm_alarm`         | VLM 复核确认，真实报警                |
| `vlm_ignore`        | VLM 复核排除，误报                    |

### status（处理状态，人工侧）

| 值                 | 含义               |
| ------------------ | ------------------ |
| `pending`        | 待处理（初始状态） |
| `confirmed`      | 人工确认报警       |
| `false_positive` | 人工确认误报       |

`level` 与 `status` 是两个独立维度：VLM 复核只改 `level`，人工操作只改 `status`。

## 3. 嵌套对象结构

### small_model（小模型检测结果）

| 字段           | 类型  | 说明                                                               |
| -------------- | ----- | ------------------------------------------------------------------ |
| `detected`   | bool  | 是否检测到目标，推送的记录恒为`true`                             |
| `confidence` | float | 置信度，与顶层`confidence` 相同                                  |
| `boxes`      | array | 检测框数组，每框为`[x1, y1, x2, y2]` 像素坐标（原图坐标系，int） |

### vlm_review（VLM 复核结果，未复核为 null）

| 字段           | 类型   | 说明                                  |
| -------------- | ------ | ------------------------------------- |
| `confirmed`  | bool   | `true` = 确认报警，`false` = 排除 |
| `confidence` | float  | VLM 置信度，0~1                       |
| `reason`     | string | VLM 复核理由文本                      |

## 4. reason 字段来源

| 阶段               | 取值规则                                                                     | 示例                                            |
| ------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------- |
| 创建时             | 算法配置了自定义报警说明 → 用配置文本；否则用模板`检测到{算法显示名}异常` | `发现明火，请立即处理` / `检测到安全帽异常` |
| VLM 复核后（覆盖） | `[VLM 确认] {理由}` 或 `[VLM 已排除] {理由}`                             | `[VLM 确认] 画面中确实存在明火`               |

## 5. 完整 JSON 示例

### 5.1 初始报警（小模型触发，未复核）

```json
{
  "id": "3_安全背心_05dc45_1784538005159",
  "camera_id": "3",
  "detection_type": "安全背心_05dc45",
  "level": "small_model_alarm",
  "status": "pending",
  "time": "2026-07-30 14:23:15",
  "confidence": 0.876,
  "reason": "检测到安全背心异常",
  "small_model": {
    "detected": true,
    "confidence": 0.876,
    "boxes": [[120, 45, 380, 420]]
  },
  "vlm_review": null,
  "source": "small_model",
  "frame_count": 5
}
```

### 5.2 VLM 复核确认后（level / reason / vlm_review 被更新）

```json
{
  "id": "3_安全背心_05dc45_1784538005159",
  "camera_id": "3",
  "detection_type": "安全背心_05dc45",
  "level": "vlm_alarm",
  "status": "pending",
  "time": "2026-07-30 14:23:15",
  "confidence": 0.876,
  "reason": "[VLM 确认] 画面中人员未穿安全背心",
  "small_model": {
    "detected": true,
    "confidence": 0.876,
    "boxes": [[120, 45, 380, 420]]
  },
  "vlm_review": {
    "confirmed": true,
    "confidence": 0.92,
    "reason": "画面中人员未穿安全背心"
  },
  "source": "small_model",
  "frame_count": 5
}
```

## 6. 记录生命周期（重要：记录创建后会发生变更）

报警记录不是创建后就不变的，存在三类变更事件，推送 API 设计需考虑：

| 事件         | 时机                                             | 变更字段                                                                             |
| ------------ | ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 创建         | 小模型检测到异常时                               | 全部字段初始化，`level=small_model_alarm`，`status=pending`，`vlm_review=null` |
| VLM 复核完成 | 创建后数秒~数十秒（异步，仅算法开启 VLM 复核时） | `level` → `vlm_alarm` / `vlm_ignore`；`reason` 覆盖；`vlm_review` 填充    |
| 人工处理     | 任意时刻（可能不发生）                           | `status` → `confirmed` / `false_positive`                                     |

已确定采用**事件推送**：创建时推一条，复核完成再推一条更新（以 `id` 关联），人工处理不推送。推送报文见第 7 节。

## 7. 推送报文

推送方式已确定为**事件推送**（创建 + VLM 复核两条报文，内嵌快照和关键帧），推送报文结构与传输约定见独立文档：[alarm_push_api.md](alarm_push_api.md)。

## 8. 图片资源

记录的图片（标注快照 + 检测帧序列）以文件形式存储在部署机，不在元数据 JSON 中。推送已确定采用 base64 内嵌（见 [alarm_push_api.md](alarm_push_api.md)）；此外接收方也可通过现有接口按需拉取（见第 9 节）。

快照图片上已绘制触发算法的检测框和时间戳水印。

## 9. 现有查询接口（供参考/联调）

| 接口                                                                                      | 说明                                            |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `GET /records?page=1&page_size=20&camera_id=&level=&dtype=&status=&date_from=&date_to=` | 分页查询记录元数据，均支持过滤                  |
| `GET /records/summary`                                                                  | 记录统计摘要（按 status/level/类型/摄像头聚合） |
| `GET /record/{record_id}`                                                               | 单条记录详情，含 base64 快照和帧序列            |
| `GET /record/{record_id}/snapshot`                                                      | 单条记录快照（base64）                          |
| `GET /record/{record_id}/frames`                                                        | 单条记录检测帧序列（base64 数组）               |

注意：`record_id` 中含中文和下划线，URL 传参需做 URL 编码。

## 10. 备注

- 时间字段 `time` 为字符串格式 `YYYY-MM-DD HH:MM:SS`（部署机本地时间），不是时间戳；记录 ID 尾部含毫秒时间戳可用于排序
- `confidence` 在旧数据中可能为 numpy 序列化后的普通 float，范围 0~1
- 检测框坐标基于摄像头原始分辨率（各摄像头可能不同），接收方如需绘制需按目标图尺寸等比缩放
